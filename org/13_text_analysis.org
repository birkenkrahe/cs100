You learn how to clean a text to generate a corpus that you can
analyze using self-generated (rather than imported) functions.

You then learn how to generate Markov chains from the text - a method
similar to parts of a Large Language Model (LLM) in chatbots.

Purpose:
- Use Python's core datastructures, lists, dictionaries, and tuples
- Use idiomatic algorithms using these data structures
- Explore text analysis and Markov chain generation
- Learn more about how an LLM operates

Topics:

Part 1: Bag of words
- Filter *unique words* from a text using a dictionary
- Remove *punctuation* from within and between words
- Compute the *word frequencies* of each unique word
- Spell-check a text using *dictionary subtraction*

Part 2: Markov chains
- Choose a *random* sequence of words from a collection
- Finding all *bigrams* (sequences of two words)
- Compute the list of words that come next (*Markov chain analysis*)
- Generate a new text that maintains *statistical* relationships

* Punctuation

Three string functions are our helpers:
1) We remove hyphens in a line and ~replace~ them with spaces.
2) We ~split~ the line to separate the words in the corpus.
3) After splitting the words we use ~strip~ to remove punctuation.

** Replace hyphens with whitespace

- The =split_line= function takes a string, replaces all dashes with one
  space, and splits the string (since there's now a whitespace):[fn:1]
  #+begin_src python :results none  :session *Python* :python python3
    def split_line(string):
        return string.replace('--',' ').split()
  #+end_src

- The two commands ~replace~ and ~split~ are chained: the string is piped
  into ~replace~, and the output is piped into ~split~.

- Check:
  #+begin_src python :results output :exports both :session *Python* :python python3

    result = split_line(string)
    print(result)

** Extension: Unicode encoding

- Characters aren't all born equal - in Python, they are encoded using
  the [[https://www.unicode.org/standard/standard.html][Unicode standard]]. Without such a standard, it would be
  impossible to compare digital texts. "Encoded in unicode" means that
  each character (e.g. on your keyboard) is mapped to a numeric code
  point represented as bytes according to some encoding scheme
  (e.g. UTF-8: ~U+0000~ to ~U+007F~ - 128 values, the whole ASCII range).

- When you enter ~open_url(...).read()~ or ~open(filename)~, Python
  decoded the raw bytes from the file into a ~str~ of Unicode code
  points based on an encoding assumption (e.g. UTF-8). If that
  assumption is wrong, you get garbled text.

- Example:
  1) ='café'= is four code points - the ='é'= is one code point (~U+00E9~)
     regardless of how it'll be stored

  2) You see that the byte translation is different for UTF-8 and
     Latin-1.

  3) When decoding a UTF-8 mapping as Latin-1, you get garbled text
     called "mojibake" (a Japanese term meaning 'character change').

  #+begin_src python :results output :exports both :session *Python* :python python3
    word = 'café'

    print('str (code points):', [hex(ord(c)) for c in word],end='\n\n')
    print('UTF-8 bytes:       ', word.encode('utf-8'))
    print('UTF-8 byte count:  ', len(word.encode('utf-8')),end='\n\n')
    print('Latin-1 bytes:     ', word.encode('latin-1'))
    print('Latin-1 byte count:', len(word.encode('latin-1')),end='\n\n')

    # show the mismatch: decoding UTF-8 bytes AS Latin-1
    utf8_bytes = word.encode('utf-8')
    print('UTF-8 bytes decoded as Latin-1:', utf8_bytes.decode('latin-1'))
  #+end_src

  #+RESULTS:

* Word frequencies

- We create a third dictionary, =word_counter=, of unique words (same
  procedure as before) but this time we increase the value when ever
  see the same word again later:

  #+begin_src python :results none :session *Python* :python python3
    word_counter = {}                     # initialize empty dict
    for line in open(filename):           # for every line
        for word in split_line(line):     # remove -- in the line
            word = clean_word(word)       # remove punctuation, lower case
            if word not in word_counter:
                word_counter[word] = 1    # word found for the first time
            else:
                word_counter[word] += 1   # word found again increase count
  #+end_src

- Now =word_counter.values= contains the frequencies. To create an
  ordered list of the most frequent words, we sort the ~items~ by each
  entry's second element as the sorting ~key~, and ~reverse~ the order.

- The ~.items()~ view can be turned into a ~list~ to be subscripted:
  #+begin_src python :results output :exports both :session *Python* :python python3

  #+RESULTS:

** Subtracting the valid word dictionary from our word dictionary

- Python functions can return dictionaries! The function =subtract=
  takes two dictionaries =d1= and =d2= as parameters and returns a
  residual dictionary =res= that contains all the keys from =d1= that are
  not in =d2=:

        res = {}
        for key in d1:
            if key not in d2:

        return res
  #+end_src

* Random numbers

- Most programs are *deterministic*: given the same input, they
  produce the same output every time. That's normally what we want -
  but sometimes (games, sampling, generating variety) we want the
  computer to be unpredictable.

- True randomness is hard to get out of a deterministic machine, so
  Python's ~random~ module instead generates *pseudorandom* numbers:
  the sequence is actually computed by a deterministic algorithm, but
  it's practically impossible to tell that just by looking at it.
  #+begin_src python :results none :session *Python* :python python3
    import random
  #+end_src

* Bigrams

- A pair of consecutive words is called a *bigram*. Three words in a
  row is a *trigram*, and a sequence of unspecified length is an
  *n-gram*.

** Counting bigrams

- We store bigram counts the same way we stored word counts, in a
  dictionary - except each *key* is now a 2-word ~tuple~ instead of a
  single string:
  #+begin_src python :results none :session *Python* :python python3
    bigram_counter = {}

    def count_bigram(bigram):
        key = tuple(bigram)          # e.g. ['of','the'] -> ('of','the')
        if key not in bigram_counter:
            bigram_counter[key] = 1
        else:
            bigram_counter[key] += 1
  #+end_src

- To build each bigram while scanning the text, we keep a small
  *sliding window* - a list holding just the last one or two words
  seen. Once the window holds two words, we count that bigram and drop
  the oldest word to make room for the next one:
  #+begin_src python :results none :session *Python* :python python3
    window = []

    def process_word(word):
        window.append(word)
        if len(window) == 2:
            count_bigram(window)
            window.pop(0)         # slide the window forward
  #+end_src

- Now run every word in the book through =process_word=, the same loop
  shape we used to build =word_counter=:
  #+begin_src python :results output :exports both :session *Python* :python python3
    for line in open(filename):
        for word in split_line(line):
            word = clean_word(word)
            process_word(word)

    print(len(bigram_counter))    # number of *distinct* bigrams
  #+end_src

  #+RESULTS:
  : 46828

- Sort =bigram_counter= the same way we sorted =word_counter= - by
  frequency, descending - to see the five most common bigrams:
  #+begin_src python :results output :exports both :session *Python* :python python3

* Markov analysis

- Instead of counting how often a pair of words occurs, we can record,
  for *every* word, the list of words that immediately followed it
  each time it appeared. This is Markov chain analysis - a simplified
  version of the same statistical idea behind how a Large Language
  Model predicts its next token.

** A small example first

- To keep the dictionary small enough to read on screen, we'll analyze
  four lines from the Monty Python song /Eric, the Half a Bee/ before
  turning the same code loose on the whole book:
  #+begin_src python :results none :session *Python* :python python3
    song = """
    Half a bee, philosophically,
    Must, ipso facto, half not be.
    But half the bee has got to be
    Vis a vis, its entity. D'you see?
    """
  #+end_src

- We'll build a dictionary =successor_map= that maps each word to the
  *list* of words seen after it. Start with the first two words of the
  song as an example:
  #+begin_src python :results output :exports both :session *Python* :python python3
    successor_map = {}
    first, second = 'half', 'a'
    successor_map[first] = [second]
    print(successor_map)
  #+end_src

  #+RESULTS:
  : {'half': ['a']}

- The next time "half" is followed by a *different* word, we ~append~
  to the existing list instead of overwriting it:
  #+begin_src python :results output :exports both :session *Python* :python python3
    first, second = 'half', 'not'
    successor_map[first].append(second)
    print(successor_map)
  #+end_src

  #+RESULTS:
  : {'half': ['a', 'not']}

- Wrapped as a function, using the same "add if new key, append if
  not" pattern as =count_bigram=:
  #+begin_src python :results none :session *Python* :python python3
    def add_bigram(bigram):
        first, second = bigram
        if first not in successor_map:
            successor_map[first] = [second]
        else:
            successor_map[first].append(second)
  #+end_src

- If a word is followed by the *same* successor more than once, that
  successor is added to the list again - so the list itself carries
  the frequency information, without needing a separate weight.

- We slide a window over the words exactly as before, but call
  =add_bigram= instead of =count_bigram=:
  #+begin_src python :results none :session *Python* :python python3
    def process_word_bigram(word):
        window.append(word)
        if len(window) == 2:
            add_bigram(window)
            window.pop(0)
  #+end_src

- Reset =successor_map= and =window=, then process the song word by word:
  #+begin_src python :results output :exports both :session *Python* :python python3
    successor_map = {}
    window = []

    for word in song.split():
        word = clean_word(word)
        process_word_bigram(word)

    print(successor_map)

- Generating text is now a two-step loop:
  1) Look up the current word's list of successors in =successor_map=.
  2) Choose one at random with ~random.choice~, then repeat, using the
     chosen word as the new current word.

- Start with a word that has several different successors, "said":
  #+begin_src python :results output :exports both :session *Python* :python python3

- Pick the next word:
  #+begin_src python :results output :exports both :session *Python* :python python3
    word = random.choice(successors)
    print(word)
  #+end_src

  #+RESULTS:
  : and

- Repeat that step in a loop to generate a longer run of text:
  #+begin_src python :results output :exports both :session *Python* :python python3
    word = 'said'
    for i in range(10):
        successors = successor_map[word]

  each step only remembers *one* word back. Using two-word keys (bigram

* Debugging

- The programs in this chapter are longer than earlier ones, and it's
  easy to get a sliding window or a dictionary-of-lists subtly wrong.
  When you're stuck, work through these in order rather than jumping
  straight to "just try things":

  1) *Read*: Read your code back to yourself, line by line. Does it
     say what you actually meant, or what you *think* you meant? This
     only catches typos and slips - if you misunderstand what
     =window.pop(0)= does, reading the line ten times won't reveal
     that, because the error is in your head, not on the screen.

  2) *Run*: Add a ~print~ at the point you're unsure about - print
     =window= right after you append to it, or print
     =successor_map[word]= right before you call ~random.choice~ on it.
     Small, targeted experiments beat large, vague ones.

  3) *Ruminate*: Stop and think before changing more code. Is this a
     syntax error, a runtime error (like the ~KeyError~ from choosing
     on a dictionary earlier in this chapter), or a semantic error
     (code runs, but the *logic* is wrong)? What did you change right
     before it broke?

  4) *Rubber-duck*: Explain the problem out loud, line by line, to
     anyone - or anything - willing to listen. You will often find the
     bug while explaining it, before the other party says a word.

  5) *Retreat*: If a program has too many things wrong with it at
     once, back up. Copy it aside, strip it down to the last version
     that worked, and rebuild from there one piece at a time instead
     of debugging all the pieces simultaneously.

  6) *Rest*: If none of the above works, stop. Come back to it later.
     It's extremely common to see the bug immediately the next time
     you look, once you're not staring at the same wrong assumption
     anymore.

- A concrete example from this chapter: if =successor_map[word]= raises
  a ~KeyError~ while you're generating text, *read* first (did you
  spell the starting word correctly?), then *run* a quick check -
  =word in successor_map= - before assuming anything more complicated
  is wrong. The most likely cause is simply that your chosen starting
  word never occurred in the book, or it only occurred as the very
  last word of the text (so it has no recorded successor).
