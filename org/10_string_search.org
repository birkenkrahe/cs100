  #+begin_quote

* Checking strings in loops

- Loops and conditionals are useful to check text passages. For
  example this quote by G.K.Chesterton:
  #+begin_quote
  "God is like the sun; you cannot look at it, but without it you
  cannot look at anything else."
  #+end_quote

- Let's store the string in a ~str~ variable:
  #+begin_src python :results output :exports both :session *Python* :python python3
    quote = "God is like the sun;\
     you cannot look at it, but without it\
     you cannot look at anything else."

    print(quote)
  #+end_src

  #+RESULTS:
  : God is like the sun; you cannot look at it, but without it you cannot look at anything else.

- The character '\' at the end of the line ensures that Python
  understands that the string is still running on.

- How many letters 'e' are in =quote=?
  #+begin_src python :results output :exports both :session *Python* :python python3
    e = 0
    for letter in quote:
        if letter == 'e':
            e += 1
            print(e)
  #+end_src

  #+RESULTS:
  : 4

- How can we make sure that there aren't any upper case 'e' letters in
  there? Perhaps like this?
  #+begin_src python :results output :exports both :session *Python* :python python3
    e = 0
    for letter in quote:
        if letter == 'e' or 'E':
            e += 1
            print(e)
  #+end_src

  #+RESULTS:
  : 92

- That sounds wrong, because 92 is the length of the whole
  sentence. So the check failed - it was always ~True~.
  #+begin_src python :results output :exports both :session *Python* :python python3
    print(len(quote))
  #+end_src

  #+RESULTS:
  : 92

- Do you know why?
  #+begin_quote
  With ~if letter == 'e' or 'E'~, Python checks if letter is 'e' or if
  'E', but not if letter is 'e' or letter is 'E'. Since the ASCII
  value of 'E' is non-zero, the expression is always ~True~.
  #+end_quote

- Let's fix it:
  #+begin_src python :results output :exports both :session *Python* :python python3
    count = 0
    for letter in quote:
        if letter == 'e' or letter == 'E':
            count += 1
            print(count)
  #+end_src

  #+RESULTS:
  : 4

- Okay, so there are no letter e or E in the quote.

- We can *modularize* such a check by putting it into a
  function =how_many_e= that returns a boolean:
  #+begin_src python :results output :exports both :session *Python* :python python3
    def how_many_e():
        count = 0
        for letter in quote:
            if letter == 'e' or letter == 'E':
                count += 1
        return count

    print(how_many_e())
  #+end_src

  #+RESULTS:
  : 4

- We can *generalize* this function beyond =quote= by making it a function
  parameter:
  #+begin_src python :results output :exports both :session *Python* :python python3
    def how_many_e(string):
        count = 0
        for letter in string:
            if letter == 'e' or letter == 'E':
                count += 1
        return count

    print(how_many_e(quote))
  #+end_src

  #+RESULTS:
  : 4

* The ~in~ operator

- The =how_many_e= function can be simplified using the ~in~ keyword:
  #+begin_src python :results output :exports both :session *Python* :python python3 
    word = "banana"
    print('a' in word)
  #+end_src

  #+RESULTS:
  : True

- So we can rewrite:
  #+begin_src python :results output :exports both :session *Python* :python python3 
    def how_many_e2(string):
        count = 0
        for letter in string:
            if letter in "eE":
                count += 1
        return count

    print(how_many_e2(quote))
  #+end_src  

  #+RESULTS:
  : 4

- And it gets better: Instead of having to check on lower and
  uppercase characters, convert them to one case, ~.upper()~ or
  ~.lower()~:
  #+begin_src python :results output :exports both :session *Python* :python python3 
    def how_many_e3(string):
        count = 0
        for letter in string:
            if letter.lower() in 'e':
                count += 1
        return count

    print(how_many_e3(quote))
  #+end_src

  #+RESULTS:
  : 4
  
* Reading from files

- Let's put our quote into a file, and then read from the file. This
  is useful for natural language programming when we want to analyse
  large amounts of text usually stored in files.

- Files can be opened to be written to and to be read from using ~open~:
  #+begin_src python :results output :exports both :session *Python* :python python3
    help(open)
  #+end_src

- The docstring is long. The essence is this:
  1) ~open~ has one mandatory argument, the =file=
  2) it opens and returns a data stream
  3) its default mode is 'read' or 'r'
  4) to open an existing file for writing, use 'w'
  5) to create and open a file for writing, use 'x'
  6) reading and writing text is the default

* Linear search

- A linear search is a search that goes along its target letter by
  letter. There are many more efficient search methods, but this is
  the simplest.

- The following function is a generalization of =how_many_e= and checks
  how many of a given =letters= argument are contained in its =word=
  argument.
  #+begin_src python :results output :exports both :session *Python* :python python3 
    def how_many(letters,word):
        """Checks how many letters are in a word"""
        count = 0
        for letter in word.lower():
            if letter in letters.lower():
                count += 1
        return count

    print(how_many('a',"Banana"))
    print(how_many('o',"banana"))        
  #+end_src

  #+RESULTS:
  : 3
  : 0

- You can also test this with more than one letter:

    print(how_many('aeiou',"Traffic control")) # a:1, i:1, o:2 = 4
  #+end_src

- Alternatively, if you only want to find out if any of a given set of
  letters can be found in the string:
  #+begin_src python :results output :exports both :session *Python* :python python3 
    def uses_any(letters,word):
        """Checks if a word uses any of a list of letters."""
        for letter in word.lower():
            if letter in letters.lower():
                return True
        return False

    print(uses_any('a',"banana"))
    print(uses_any('o',"banana"))    
  #+end_src

  #+RESULTS:
  : True
  : False

* Doctest

- You can also use a docstring to *test* a function, for example ~uses_any~:

  #+begin_src python :results none :session *Python* :python python3 
    def uses_any(letters,word):
        """Checks if a word uses any of a list of letters.
        >>> print(uses_any('a',"banana"))
        True
        >>> print(uses_any('o',"banana"))    
        False
        """
        for letter in word.lower():
            if letter in letters.lower():
                return True
        return False
  #+end_src

- To run these tests, you need to import a new module and run a
  special function:
  #+begin_src python :results output :exports both :session *Python* :python python3 
    from doctest import run_docstring_examples

    print(run_docstring_examples(uses_any,
                                 globals(),
                                 name=uses_any.__name__)) # None
  #+end_src

  : None

- Two of these parameters, =globs= and =name=, sound intimidating, but
  they connect to something you already know:
  #+begin_quote
  You've already met ~__name__~: Python sets it for every file, and
  =if __name__ == "__main__":= checks its value to decide whether the
  file is being run directly. ~__name__~ doesn't float around on its
  own - it's one entry in a big dictionary that Python keeps of every
  name your file knows about (functions, variables, imports, and yes,
  ~__name__~ itself). That dictionary is exactly what ~globals()~
  returns.

  ~run_docstring_examples~ has to *execute* the =>>> ...= lines written
  inside a docstring, as if you had typed them yourself at the prompt.
  To do that, it needs to know what names like ~uses_any2~ actually
  refer to - so you hand it your whole "name book" with ~globals()~,
  the same dictionary ~__name__~ lives in.

  ~name=...~ is much simpler, and does nothing to the test itself: it
  is only a label attached to failure messages, so that when you are
  doctesting several functions, you can tell which one just failed.
  Purely cosmetic.
  #+end_quote
